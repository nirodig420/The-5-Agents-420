## 2. הארכיטקטורה המומלצת

### הבעיה המרכזית, במילים פשוטות

Make הוא שירות ענן. הוא לא יכול "להסתכל" על תיקיות במחשב שלי. הקובץ נוצר היום בתיקייה
מקומית בשולחן העבודה, ולכן צריך תחנת ביניים בענן. החדשות הטובות: במחשב שלי כבר מותקן
Google Drive for Desktop (כונן G:). כל קובץ שנשמר בתוך G: עולה לענן מעצמו תוך שניות.

### המלצה A (המועדפת): עותק ל-Drive + טריגר "שומר" יומי

1. **שינוי קטן במשימה המתוזמנת הקיימת (Cowork):** בנוסף לשמירה בתיקייה הרגילה, היא
   תשמור עותק של הקובץ גם לתיקייה ייעודית חדשה בתוך כונן G:, למשל:
   `G:\My Drive\טל חשבוניות\לשליחה\`. תיקייה נקייה שמכילה רק את קובצי החיוב, שום דבר אחר.
2. **תרחיש Make עם טריגר Google Drive "Watch files in a folder"** על התיקייה הזו,
   שרץ **פעם ביום ב-10:00**. רוב ימות החודש הוא מוצא תיקייה ריקה ונרדם (עלות: פעולה
   אחת ביום). ביום שהקובץ החדש מופיע, הוא תופס אותו ושולח.
3. **שליחה בוואטסאפ דרך Green API** (החיבור שכבר קיים בחשבון ומשמש את תרחיש 5618188).
   Green API יודע לשלוח קבצים למספרים פרטיים רגילים בפקודת sendFileByUpload, עד 100MB,
   אז קובץ אקסל קטן עובר בקלות.
4. **הודעת סיכום לטלגרם שלי** (הבוט הקיים Bot connection GA4, chatId 352155152):
   הצלחה עם שם הקובץ, או התראת כשל אם משהו נשבר.

**למה ככה:** הטריגר "מחכה לקובץ" ולא לתאריך. אם המשימה של Cowork תרוץ באיחור, אם
המחשב היה כבוי ב-28 והיא רצה רק ב-29, או אם הסנכרון של Drive התעכב, זה לא משנה.
ברגע שהקובץ מגיע לענן, למחרת ב-10:00 לכל המאוחר הוא נשלח. עמיד, פשוט, וזול.

### חלופה B: תזמון קבוע ב-28 לחודש + חיפוש לפי שם

תרחיש שרץ פעם בחודש בלבד, ב-28 ב-10:00 (אחרי שהמשימה של Cowork סיימה), עם מודול
Google Drive "Search for files/folders" שמחפש קובץ בשם מדויק שנבנה בנוסחה:

**יתרון:** עלות כמעט אפסית (רץ 12 פעמים בשנה). **חיסרון:** שביר לתזמון. אם הקובץ נוצר

## 3. פירוט המודולים צעד-אחר-צעד (המלצה A)

תרחיש חדש אחד, שם מוצע: `🤖NIRO — שליחת חיוב חודשי לטל (WhatsApp)`.
טריגר אחד לתרחיש, לפי כללי הבית.

### מודול 1: Google Drive · Watch files in a folder (הטריגר)

- **מה הוא עושה במילים פשוטות:** בודק פעם ביום אם נוסף קובץ חדש לתיקייה שבחרנו.
- **Connection:** חשבון Google של ניר (זה שה-Drive שלו מסונכרן לכונן G:). לאימות בעורך
  איזה חיבור Google Drive כבר קיים בחשבון ה-Make.
- **Folder:** התיקייה הייעודית `טל חשבוניות/לשליחה` (נבחרת מתוך עץ התיקיות במודול).
- **Watch:** By Created Time (רק קבצים חדשים, לא כל עריכה של קובץ ישן).
- **Limit:** 1.
- **Scheduling:** פעם ביום, 10:00, אזור זמן Asia/Jerusalem.
- **נקודת התחלה:** From now on (שלא ישלח בטעות קבצים ישנים שכבר בתיקייה).

### מודול 2: Filter (על הקו בין 1 ל-3)

- **מה הוא עושה:** שומר סף. מוודא שזה באמת קובץ חיוב ולא קובץ אחר שנשמר בטעות בתיקייה.
- **תנאי:** File name · Starts with · `חיוב_מאמנת_` וגם File name · Ends with · `.xlsx`.
- הערה: לשים לב לגרשיים בשם הקובץ. המשימה של Cowork מנרמלת גרשיים, אז השם נקי,
  אבל אם הפילטר לא יתפוס בבדיקה, הדבר הראשון לבדוק הוא תו גרש שונה בשם.

### מודול 3: Google Drive · Download a file

- **מה הוא עושה:** מוריד את תוכן הקובץ מהענן אל תוך הריצה של Make, כדי שיהיה מה לצרף.
- **File ID:** ממופה מהטריגר (מודול 1).

### מודול 4: Green API · שליחת קובץ (sendFileByUpload)

- **מה הוא עושה:** שולח את הקובץ לוואטסאפ של טל כמסמך מצורף, בדיוק כמו לצרף קובץ ידנית.
- **Connection:** חיבור ה-Green API הקיים (זה שמשמש את תרחיש 5618188).
- **שם המודול המדויק בעורך:** לאימות ברשימת המודולים של Green API בעורך (צפוי "Send a
  File" או דומה). אם אין מודול קובץ מובנה, חלופה מיידית: מודול HTTP · Make a request אל
  `POST .../sendFileByUpload` של Green API, עם אותו חיבור מפתחות.
- **chatId:** `972549773321@c.us` (זה הפורמט של Green API למספר פרטי: קידומת מדינה בלי
  אפס, ואז הסיומת `@c.us`).
- **File:** התוכן שהורדנו במודול 3.
- **fileName:** ממופה משם הקובץ במודול 1 (חייב לכלול את הסיומת .xlsx).
- **Caption (הודעה מצורפת, טיוטה):** "היי טל, מצורף קובץ החיוב לחודש. שתהיה שנה טובה
  של עבודה משותפת" או נוסח קצר אחר שניר יבחר. אם רוצים נוסח מושקע יותר, זה של יעל.

### מודול 5: Telegram Bot · Send a Text Message (אישור הצלחה)

- **Connection:** Bot connection GA4 · **Chat ID:** 352155152.
- **טקסט:** `✅ קובץ החיוב {{שם הקובץ ממודול 1}} נשלח לטל בוואטסאפ`.

### טיפול בשגיאות (Error Handler)

- על מודול 4 (השליחה): מסלול שגיאה עם Telegram · Send a Text Message
  (`❌ שליחת החיוב לטל נכשלה: {{הודעת השגיאה}}`) ואחריו **Break** עם Retry אחד כעבור
  15 דקות. ככה תקלה רגעית של Green API מנסה שוב לבד, ואם גם זה נופל, אני יודע מיד.
- על מודול 3 (ההורדה): אותו דפוס, התראה + Break.

### לפני הפעלה

חובה להריץ את הסקיל `make-scenario-check` על התרחיש לפני Run once ולפני ON
(כולל הבדיקה שהתרחיש לא נשאר On demand, ושעריכה לא כיבתה אותו).

## 6. עלות משוערת ב-Operations

- טריגר יומי שמוצא תיקייה ריקה: פעולה אחת ביום × ~29 ימים = **~29 פעולות**.
- ביום השליחה: טריגר + הורדה + שליחת Green API + טלגרם = **4 פעולות**.
- **סה"כ: ~33 פעולות בחודש.** זניח לחלוטין (פחות מ-0.4% מחבילה של 10,000).
- חלופה B הייתה עולה ~4 פעולות בחודש, אבל ההפרש של ~29 פעולות לא שווה את השבירות.
- בצד Green API: הודעה אחת בחודש, רחוק מכל מגבלת קצב. גודל קובץ אקסל: זעיר מול תקרת
  100MB.
